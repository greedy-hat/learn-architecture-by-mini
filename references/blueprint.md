- 原项目：仓库、分支或 commit。

## 示例：异步任务学习切片

若源码确实采用队列，保留“提交 → 入队 → worker 执行 → 更新状态 → 查询结果”。可将外部计算替换为确定性本地计算，并缩小 worker 数量。仍需展示等待与执行的分离。

- 正常场景：提交任务后最终得到结果，状态转换符合源码契约。
- 失败场景：注入一次执行错误，观察源码所定义的失败或重试行为。
- 幂等场景：仅当原流程要求幂等时验证重复提交或重复消费。
- 若删除持久化，明确进程重启会丢失任务，无法据此学习恢复机制。

## 递进练习

1. 预测一次输入经过的模块及状态变化，再运行核对。
2. 改变一个边界行为，例如返回错误，检查传播和不变量。
3. 在原项目找到对应实现，解释生产版本新增机制解决的问题。
